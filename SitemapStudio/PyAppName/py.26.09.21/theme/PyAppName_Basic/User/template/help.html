DOCUMENTATION

Capture with confidence.

A guide to sitemap discovery, local screenshot storage, responsible crawling and GitHub publishing.

01

Provide sitemap sources

Paste one or more HTTP(S) sitemap URLs. Sitemap index files are followed recursively, and duplicate page URLs are removed before capture.

02

Choose the capture scope

Select Full sitemap to capture every discovered unique URL, or choose a URL limit for a smaller test run. The full sitemap option can contain a very large number of URLs.

03

Save on this PC

Choose a local folder to save JPEG screenshots directly. This mode does not require a GitHub account, repository URL, personal access token or screenshot upload.

04

Publish to GitHub

Optionally choose GitHub as the destination. Provide a fine-grained personal access token scoped to one repository with Contents: Read and write. Images are committed in batches.

SECURITY & LIMITATIONS

Know what the scanner can and cannot see.

  • Only public HTTP(S) destinations are allowed. Private and local IP addresses are blocked.
  • The scanner captures URLs present in sitemap files; it does not discover login-only dashboards, modal states, or authenticated product screens.
  • Robots.txt restrictions and crawl-delay are respected. This software does not bypass bot protection, authentication, rate limits or access controls.
  • Local mode writes images directly to your chosen folder. Keep enough free disk space for large sitemap captures.
  • GitHub mode stores uploaded screenshots in your repository. Its API quota and repository storage limits apply.
  • GitHub tokens are held in process memory only and are not stored in the local database or log files.
  • Use a URL limit for a small test. Full sitemap capture may take a long time when a sitemap contains hundreds of thousands of URLs.
  • Eel maintenance: Eel is used because this app explicitly requires it, but its upstream repository is archived. Review this dependency before commercial enterprise distribution.
