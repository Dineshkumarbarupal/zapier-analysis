DOCUMENTATION

Scan with confidence.

A practical guide to sitemap discovery, responsible screenshot capture, and GitHub publishing.

01

Provide sitemap sources

Paste one or more HTTP(S) sitemap URLs. Sitemap index files are followed recursively, and duplicate page URLs are removed before capture.

02

Connect GitHub

Use a fine-grained personal access token scoped to one repository with Contents: Read and write. The app reads the selected branch and commits screenshot batches.

03

Capture pages

Chromium opens each permitted URL. The app follows the site's robots.txt policy, captures a JPEG, and records title and capture mode.

04

Upload and clean up

Images are uploaded in batches. Local temporary images are deleted only after GitHub confirms the branch commit. Failed uploads keep local files for recovery.

SECURITY & LIMITATIONS

Know what the scanner can and cannot see.

  • Only public HTTP(S) destinations are allowed. Private and local IP addresses are blocked.
  • The scanner captures URLs present in sitemap files; it does not discover login-only dashboards, modal states, or authenticated product screens.
  • Robots.txt restrictions and crawl-delay are respected. This software does not bypass bot protection, authentication, rate limits, or access controls.
  • GitHub stores uploaded screenshots permanently until you delete them. Local cleanup does not reduce remote repository storage.
  • GitHub token is held in memory during the run and is not stored in the local database or log files. The connection test checks repository/branch access; the first screenshot commit confirms write access.
  • Large scans can take a long time. Use a small URL limit to test first; restart a scan with the same repository to reuse already-uploaded URL records and recover captured-but-uncommitted files.
  • Eel maintenance: Eel is used because this app explicitly requires it, but its upstream repository is archived. Review this dependency before commercial enterprise distribution.
